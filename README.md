# ddq-review

审阅和最小修订已有 DDQ、尽调问卷与 white paper 草稿的 Codex Skill。

## 工作流程

确认需求与依据范围 → 完整审阅 → 提交具体修改及批注方案 → 使用者确认 → 生成三份同格式文件。

- **Clean**：采用已确认修改的正文，用于对外交付。
- **Clean＋Comments**：相同正文，附给同事复核的原生批注。
- **详细审阅版**：修改前后、词句级变化、原因、依据原文及确认状态。

## 核心原则

- 默认最小修改，保留原有结构和措辞。
- 可将律师意见、Terms 或指定文件设为唯一依据。
- 资料未说明不等于事实不存在；冲突和不确定项单列确认。
- 默认不进行网络查询，特殊需要须先获使用者确认。
- 明确基准版本及历史修订处理方式。
- 已批准的修改直接执行，新增实质问题另行确认。
- Comments 写清复核事项、实际改动及具体条款依据。
- 三版正文同源，Clean 不混入内部批注和审阅过程语言。

## 安装

将下面的 prompt 复制到支持 Skill Installer 的 Codex 环境：

```text
请使用 $skill-installer 安装以下 GitHub 仓库中的技能：

仓库：https://github.com/raymondhuang1994/ddq-review-public
分支：main
技能目录：仓库根目录（路径为 .，包含 SKILL.md）
技能名称：ddq-review

安装前检查技能说明和随附文件。
如果已存在同名技能，先比较差异并向我确认，不直接覆盖。
安装后确认安装结果，并给出一条调用示例。
不要向 GitHub 上传任何本地材料。
```

技能目录需要完整保留 `SKILL.md`、`references/` 和 `agents/` 的相对结构。

## 使用

每次提供待审 draft、版本或比较基准、指定参考依据和处理范围；同时说明依据是否唯一、正文及 Comments 的语言、输出格式和已确认事项。没有参考依据时明确说明，不能让模型自行补足业务事实。

```text
请使用 $ddq-review 审阅附件 draft。
比较基准：〔版本及历史修订处理方式〕。
指定依据：〔文件及版本〕；依据规则：〔唯一依据／主要依据与补充范围〕。
处理范围：〔全文／题号或章节〕。
语言要求：〔正式正文、Comments、详细版分别使用的语言〕。
默认尽量少改动原文；仅使用本次提供的材料，不自行联网。
先集中确认缺失需求，再给出具体修改方案及拟加 Comments。
我确认后，按 draft 格式生成 Clean、Clean＋Comments 和详细审阅三版。
```

用户只要求核对、比较或讨论时，不自动生成完整三版。实际制作 Word、Excel 或读取 PDF 时，需要环境中相应的文件技能和工具；本仓库提供审阅流程，不包含文档生成引擎。

## 材料边界

本仓库只包含通用工作流程和占位模板，不包含客户案例、业务附件或个人审阅记录。将实际任务材料和生成文件保存在独立目录，不提交本仓库。`.gitignore` 使用发布文件白名单，提交前仍需检查实际暂存内容。

## 文件

- [SKILL.md](SKILL.md)：适用范围、原则与确认流程。
- [references/review-method.md](references/review-method.md)：基准、证据、修改记录与双语核对。
- [references/deliverables.md](references/deliverables.md)：三版交付、Comments、词句级标记与验收。
