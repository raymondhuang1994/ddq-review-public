# 三版交付与 Comments

在提出文件交付方案、拟写批注或生成文件前读取。默认三份相同格式的文件，除非使用者明确另有要求。

## 1. 共用一份已确认内容

先建立已确认的正文结果，再派生 Clean 和 Clean＋Comments；详细版的“采用后正文”或“修改后”字段也引用该结果，不分别重新生成。

未采纳建议或未决候选写在明确的审阅区域，不混入“已采用修改后”字段。三版的题号、章节对应、数据、术语、条件和正式答案必须一致。

默认保持 draft 的文件格式：Word 生成三个 Word，Excel 生成三个 Excel。特殊格式不能保真处理时，先提出可行替代格式或处理范围，并获得确认；不要静默转为 Markdown、PDF 或普通文本。

文件数量按用途计算。英文 Clean、英文 Clean＋Comments、中英双语详细版仍是三份；如果要求中英文各自独立的三版，需要先确认增加的文件数量。

## 2. Clean：对外交付正文

- 保留原题、编号、章节、表格、必要交叉引用和原有版式，落实已确认改动。
- 无内部批注、历史／本轮修订标记、修改高亮或工作记录；不夹带“请确认”、证据分析和待同事处理的说明。
- 正文直接陈述可采用的答案，不加入资料读取、内部核对或模型生成过程的说明。
- 保留界定权利、义务、条件或适用范围所必需的实质性文件引用。不要机械删除所有 “according to” 或文件名称。
- 不新增模板套话、营销式判断或缺乏依据的专业表述来填满答案。
- 未决事实必须按已确认方案处理。使用者允许 TBC 时可以保留，但文件状态应说明仍待完成，不能称为已可对外定稿。TBC 也不能仅放入批注而让 Clean 正文看起来已经确定。
- 对内部批注、隐藏内容和历史修订做交付前检查；发现客户不应看到的内容时，按确认范围清理或提出具体处理，不能破坏业务公式或必要材料。

## 3. Clean＋Comments：供同事审阅

正文与 Clean 完全一致，只增加真实批注。文件标明供内部审阅，不能当作无内部意见的客户净稿。

### 批注的内容

通常用两到四句，足以回答：

1. 请同事确认或复核什么？
2. 本处具体改了什么，或为什么暂不修改？
3. 根据哪份文件、哪一条；还有什么条件未定？

语气像给同事写工作批注，直接、礼貌、可采取行动。不写模型分析过程，不只说“请确认”，也不以“符合律师意见”代替来源定位。

| 状态 | 合适写法 |
|---|---|
| 已批准，供同事复核表述 | “请复核本处修改。根据《文件名》第X条，已将……调整为……，并保留……条件。” |
| 实际安排或参数尚未定 | “请确认……。第X条仍将……列为待确认，本次未写入确定的……。请提供确认后的安排。” |
| 可选建议尚未采用 | “建议……，原因是……。请确认是否采用；目前正文保留原表述。” |
| 原文已有但唯一依据未覆盖 | “请确认……安排及其依据。指定文件未覆盖该项描述；目前按已确认方案保留／标为待确认。” |

已由使用者批准的修改不能又笼统标成“待确认”。若仍请其他同事复核，明确复核对象是事实、表述还是最终采用决定；不能暗示已经获得并不存在的律师或同事批准。

### 占位模板

以下仅展示批注结构。方括号中的内容必须替换为本次资料支持、且与确认记录一致的内容；不得编造条款号或事实：

> 请复核〔具体表述〕。根据《指定文件》第X条，已将〔原表述〕调整为〔修改后表述〕，并保留〔适用条件〕。请复核本处表述与已批准修改是否一致。

> 请确认〔具体待决事项〕。《指定文件》第X条仍将〔相关内容〕列为待确认，本次按已确认方案〔说明正文处理〕。请提供〔所需确认或补充依据〕。

如批注需英文或双语，按已确认语言输出，保持状态及语气一致。未指定负责同事时，不编造姓名、头衔或职责；可省略称呼，直接以“请确认〔具体事项〕”开头，并继续说明修改内容及依据。

### 原生批注与锚点

- **Word：** 使用真实 Word Comments，锚定相关词句或段落；不能用正文括号、脚注或文末表格冒充批注。整句删除的事项可锚定到结果稿中对应段落，并在批注说明原位置和删除内容。
- **Excel：** 使用回复单元格上的原生批注或备注（Comments／Notes，按工具实际能力如实说明），不将内部意见放进正式回复文本。不能将额外说明列冒充原生批注。
- 一个批注对应一个实质事项；同一事项涉及多处，相关位置保留一致 ID。纯格式变化无需机械地逐词加批注。
- 因为 Clean 无改动高亮，不能靠改变正文或正文格式实现批注定位。Comments 版仅增加批注，不重新润色答案。
- 若工具不能可靠保留原生批注，先说明限制并提出替代方案供确认，不能在交付时声称已实现。

## 4. 详细审阅版

每项至少包含：

| 字段 | 要求 |
|---|---|
| 事项编号与位置 | 稳定 ID，题号／条款／工作表及单元格，全部受影响位置。 |
| 修改前 | 从锁定基准逐字摘录，可原样定位；辅助中文另标译文。 |
| 修改后 | 完整可读的采用后句子或段落；未采用候选单列。 |
| 具体改动 | 新增、替换、删除的词句，不能仅高亮整段。 |
| 修改原因 | 原文问题、修改必要性及其影响。 |
| 修改依据 | 来源版本、条款／页码／单元格和支持该改动的准确原文，保留关键条件及上下文；双语版附译文。 |
| 确认状态 | 已批准、保留、未决或暂缓；与用户决定记录一致。 |

根据原稿组织：

- **Word：** 按已确认事项分类，类内依正文顺序排列；必要时保留正文对照。已确定分类和编号不擅自重排。
- **Excel：** 在独立详细版中保留题号、问题和原回复，增设上述审阅字段或独立审阅工作表；仅记录有变化／有疑问的事项即可，未变内容不制造差异。根据确认方案处理双语布局，避免横向表格无法阅读。

### 词句级标记

- 新增／替换：优先只高亮改变的具体词句；不把整段、整行或整个单元格染色当成精确差异。
- 删除：在“修改前”用删除线或明确删除标记展示；“修改后”保持完整可读，不夹旧字。
- 替换：旧词在修改前可识别，新词在修改后突出。
- Word 可使用词级黄色高亮。Excel 若不能对单元格内部分文字设背景色，使用富文本颜色／加粗标记实际改动，配清楚图例；在输出方案中说明该格式适配，不宣称整格黄色就是词级高亮。
- 变化标记与 TBC 标记要可区分，不用同一颜色含混表示两个含义。任何颜色都辅以字段或文字说明。
- 中英双语的改动分别标注；中文表达不同不能作为省略英文实质变化的理由。

## 5. 交付前验收

### 内容与范围

- 每条“修改前”能在锁定基准定位；无历史删除文字混入。
- 每处实质变更已批准且有指定依据支持，或明确按用户确认的变更后依据范围处理；未批准的可选优化没有进入正文。
- 原题、条款、限制、数字和跨题引用没有遗漏；没有把未知写成 No／N/A。
- 参考原文引述准确、定位有效；不存在虚构条款或把推论标成原文。
- 两种语言的主体、否定、条件和承诺强度一致。

### 三版一致与批注

- Clean 与 Comments 版正文、数据和必要格式一致；差别仅为批注及必要文件标识。
- 详细版“修改后”与采用正文一致，删除／替换均可追踪；未决建议与已采用结果分开。
- Clean 无内部意见和修订残留；Comments 是真实对象、语言正确、锚点准确、事项状态正确。
- 客户净稿不夹带作者备注、内部附件或工作用隐藏内容；如发现需决策的清理动作，单独报告。

### 格式与可用性

- 文件可打开、编辑；Word 做渲染检查，避免表格溢出、字体缺失、截字、异常空白或关键句断裂。
- Excel 检查列宽、换行、行高、题号、筛选／冻结及原有公式、数据验证和必要样式；关键内容可见且批注可读取。
- 不把程序生成成功当作版式和语义验收通过；如工具或环境限制导致某项未验证，交付时具体说明。

完成后只交付请求范围内的文件，简要说明用途、未决事项及验证限制。无额外授权，不代发邮件、不上传客户渠道、不替任何人签署或批准。
